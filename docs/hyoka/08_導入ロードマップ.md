# 08. 導入ロードマップ（6ヶ月で本運用へ）

> 制度を一度に全部入れると、必ず現場が拒否します。
> **「測る → 慣らす → 効かせる」の順**で入れてください。

---

## Month 0：現状を数字で把握する（1ヶ月）

**「なんとなく辞める」「なんとなく忙しい」を放置しない。まず測ります。**

| 測るもの | 出し方 | なぜ必要か |
|---|---|---|
| 1人あたり月間訪問件数の**分布** | 個人別・拠点別に12ヶ月分。平均ではなくヒストグラム | 75件ボーダーの現実的な距離が分かる |
| 経験年数 × 件数の相関 | 年次ごとの平均件数 | 「3年目以降が一番多い」なら、危機はすでに進行中 |
| 離職率（全体・入社1年以内） | 直近3年 | 制度の最終KPI。ここが動かなければ全部無意味 |
| 退職者の**順番**の分析 | 退職者ごとに「負荷が上がった時期／会話が減った時期／退職申出」を時系列で並べる | 自社版の「退職の順番」が分かる |
| 記録の期限遵守率 | 直近6ヶ月 | NVA枠が機能するかの土台 |
| 加算取得率 | 加算別・利用者別 | 件数を下げても収支を保てるかの余地 |
| キャンセル率・空き枠率 | 直近6ヶ月 | 同上 |

### この月の成果物

```
□ 件数分布グラフ（個人別・拠点別）
□ 離職コストの自社試算（採用費＋教育＋生産性ロス＋残った人の負荷）
□ 「件数10件減 vs 離職2名減」の損益比較 ← 経営判断の根拠
□ 退職者の時系列分析（3〜5名分）
```

> **この4つが揃わないと、75件は「社長の思いつき」として扱われます。** 逆に揃えば誰も反対しません。

## Month 1：設計を確定し、評価者を訓練する

| 週 | やること |
|---|---|
| 1週 | 等級と件数ボーダーを確定（[01](01_設計思想と件数ボーダー.md)の表を自社数値に置換） |
| 2週 | 評価項目を管理者と一緒にレビュー。**現場の言葉に直す**（1〜2項目は現場の提案を採用すること。当事者意識が変わります） |
| 3週 | **評価者訓練（半日）**：架空の3事例に管理者全員が採点 → ズレを議論 → 基準を合わせる |
| 4週 | 全社説明会。**「なぜ75件なのか」を経営が自分の言葉で説明する** |

### 全社説明会で必ず言うこと

1. **これは楽をさせる制度ではなく、時間の使い道を変える制度です**
2. **件数を多く回した人が偉い、という評価はもうしません**
3. **その代わり、空いた時間で何を返すかを一緒に決めます**
4. **超過は本人の頑張りではなく、管理者の設計ミスとして扱います**
5. **半年間は評価を処遇に反映しません。まず慣らします**

> 5番目が最重要です。**いきなり給与に効かせると、制度への抵抗が制度の中身への抵抗にすり替わります。**

## Month 2〜3：試行（処遇には反映しない）

| やること | 目的 |
|---|---|
| 自己評価のみ実施（24項目） | 項目の意味が伝わるか確認。**分かりにくい項目を洗い出して書き換える** |
| 月次1on1（15分）を開始 | 型に慣れる。**この習慣化が制度の8割** |
| パルスサーベイ開始（月1回・3〜5問） | 晴れ／曇り／雨。データが溜まるまで3ヶ月かかる |
| 週次モニタ（件数・オンコール・パルス）を管理者が開始 | 「数字になる前」を見る訓練 |
| 判断ログを管理者が開始（月1件） | 管理者育成の資産づくり |
| 入社3ヶ月目の本部訪問を開始 | 最も離職が多い時期への先回り |

**この期間は点数を誰にも見せません。**「練習期間である」ことを繰り返し伝えてください。

## Month 4：一次・二次評価＋キャリブレーションの試行

| やること |
|---|
| 本人の自己評価 → 管理者の一次評価（**根拠の事実を必ず記入**） |
| EMの二次評価 |
| **キャリブレーション会議を実施**（90分）。拠点間の甘辛を実際に見る |
| 評価面談を実施（処遇には反映しないことを明言したうえで） |
| 制度の振り返り：**使いにくい項目・重複している項目を削る** |

> **ここで項目を削る覚悟を持ってください。** 24項目のうち2〜3個は必ず「測れない／重複」が出ます。
> 増やすのではなく減らす方向で調整すると、制度は長持ちします。

## 7ヶ月目以降：逓減のサイクル

```
半期ごとに以下を確認し、次の逓減（G4→70件、G5→65件…）を判断する

□ 件数を下げた等級で、NVA枠の成果が実際に出ているか
□ 拠点収支が悪化していないか（悪化しているなら単価か稼働で取り返せているか）
□ 離職率が改善しているか（特に入社1年以内）
□ 件数の「ばらつき」が縮んでいるか（平均ではなく分散）
□ 記録期限遵守率が落ちていないか（＝NVA枠が休憩に化けていないか）
```

**5項目のうち2つ以上が悪化していたら、次の逓減は止めて原因を潰します。**
年次逓減は「毎年自動で下げる」ものではなく、**成果が確認できた等級から順に下げる**運用にしてください。

## 導入の失敗パターン（先回りで潰す）

| 失敗 | 兆候 | 対策 |
|---|---|---|
| 管理者が評価に時間を割けない | 一次評価の根拠欄が空白 | 管理者の件数ボーダーを先に下げる。**評価より先に時間を渡す** |
| 「結局、件数を回した人が評価される」と思われる | 現場からの質問が件数の話ばかり | 最初の評価で、**件数が少なくNVA枠で成果を出した人を明確に高評価する** |
| 項目が多くて形骸化 | 自己評価が全部2点で提出される | 項目を削る。24 → 16でも構いません |
| 制度だけ立派で判断は変わらない | 判断ログが提出されない | EMが管理者会議で毎月1本読み合わせる。読まれない記録は書かれません |
| 数字は正常なのに現場が崩壊 | パルスが「雨」なのに件数・収支は良好 | [09_制度が壊れる兆候.md](09_制度が壊れる兆候.md) を月次で確認 |
