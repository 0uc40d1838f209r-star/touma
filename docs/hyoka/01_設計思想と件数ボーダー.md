# 01. 設計思想と件数ボーダー

## 1. 何を決めたのか

> 1人あたり月間訪問件数のボーダーを、**3年目以降は75件**に下げる。
> そこからさらに、**年次が上がるごとに段階的に下げていく。**

これは「楽にする」制度ではありません。**時間の使い道を変える**制度です。

## 2. なぜ件数を下げるのか（3つの理由）

### 理由1：離職は人間関係の問題に見えて、業務負荷から始まる

退職に至る順番はほぼ決まっています。

```
業務負荷が上がる → 心の余裕がなくなる → 会話が減る
→ 人間関係が壊れる → 「人間関係が理由で」退職
```

人間関係が壊れてから手を打っても遅い。**負荷が上がる前に上限を引くのが唯一の先回り**です。
訪問看護では、負荷は「件数 × 重症度 × オンコール」で決まります。
件数はこの中で**唯一こちらが直接コントロールできる変数**です。だから件数に線を引きます。

### 理由2：3年目以降は、訪問以外にしかできない仕事が発生する

1〜2年目は「自分の訪問を成立させる」ことが仕事です。
しかし3年目以降、その人にしかできない仕事が出てきます。

- 新人の同行・プリセプター
- 困難事例のセカンドオピニオン
- 記録・計画書の品質担保
- ケアマネ・医師・病院連携室との関係づくり
- オンコールの中核
- 事故・クレームの一次対応

**これらは訪問件数に一切カウントされません。**
件数ボーダーを下げないまま同じ人にこれらを乗せると、
「一番できる人が一番先に潰れる」という、訪問看護で最も多い壊れ方をします。

### 理由3：管理者は「例外の連続」を処理する職種で、時間の余白が判断の質を決める

管理者は、医療判断・家族感情・ハラスメント・職員メンタル・労務・法令・営業・多職種調整・
緊急対応・看取り・地域関係・事故対応・行政対応を同時に処理します。
しかもこれらは**互いに矛盾します**。

| 矛盾する要求 | 具体例 |
|---|---|
| 利用者優先 ⇔ 職員保護 | ハラスメント傾向のある利用者を切るか、担当を替えるか、続けるか |
| 24時間対応の維持 ⇔ 労基法遵守 | オンコール明けの訪問をどうするか |
| 売上維持 ⇔ 適正算定 | 算定要件がグレーな加算を取るか取らないか |

これは手順書では処理できません。**考える時間がない管理者は、必ずどちらか一方に倒れます。**
管理者の件数を下げるのは、判断する時間を確保するための投資です。

## 3. 年次別 件数ボーダー（設計案）

> 数値は**設計の型**です。地域特性・移動距離・重症度・保険割合で調整してください。
> 調整の式は「5. 収支を落とさない条件」に置いています。

| 等級 | 目安年次 | 月間訪問件数ボーダー | 空いた時間（NVA枠）の使途 |
|---|---|---|---|
| **G1** 新人 | 〜12ヶ月 | 立ち上げ（40 → 80件へ段階的に） | 同行・学習・記録の型づくり |
| **G2** 一人前 | 13〜24ヶ月 | **80件**（標準＝件数インセンティブの基準） | 自立運用。NVA枠は最小 |
| **G3** 中堅 | 3年目〜 | **75件**<br>※**当たり前制度クリアが条件**。未クリアは80件のまま | 月8〜10時間：新人同行・記録レビュー・困難事例の相談役 |
| **G4** リーダー | 4年目〜 | **70件**<br>※75件を2期維持＋NVA成果が条件 | 月17〜20時間：チーム運営・新規受け入れ判断・連携先訪問 |
| **G5** 主任／サブ管理者 | 5年目〜 | **65件**<br>※G4を2期維持＋拠点運営の一部を担うことが条件 | 月26〜30時間：シフト設計・教育計画・管理者代行 |
| **管理者** | — | **40〜50件** | 拠点運営・面談・営業・法令対応・矛盾の調整 |
| **エリアマネージャー** | — | **0〜20件**（緊急バックアップのみ） | 拠点間の平準化・管理者育成・制度設計・地域開拓 |

**逓減幅は「年5件」を基本**とし、G5以降は等級で管理します（年数だけで下げ続けない）。

> **重要：80件が標準であり、件数インセンティブの基準です。**
> 75件は年次で自動的に下がるものではなく、**当たり前制度をクリアした人だけに渡す枠**です。
> ゲートの判定ルール、失効事由、インセンティブと役割手当の設計は
> **[10_当たり前制度ゲートとインセンティブ.md](10_当たり前制度ゲートとインセンティブ.md) が正本**です。必ずそちらを先に読んでください。

### NVA枠（Non-Visit Activity 枠）という考え方

件数を下げると、時間が空きます。この時間を本パッケージでは **NVA枠** と呼びます。

```
NVA枠（時間/月） ≒ （前等級のボーダー − 自等級のボーダー）× 1.5〜2.0時間
                   ※移動・記録込みの1件あたり所要時間
例：G2(80件) → G3(75件) なら 5件 × 1.75h ≒ 月8.75時間
    G3(75件) → G4(70件) なら さらに 5件 ≒ 月8.75時間（累計 約17.5時間）
```

**NVA枠は「自由時間」ではなく「使途を契約した時間」です。**
四半期の初めに、本人と管理者で下記のように使途を決め、評価はその達成で見ます。

| NVA枠の使途 | 紐づく大項目 | 測り方の例 |
|---|---|---|
| 新人同行・プリセプター | ④支援行動 ⑦学習と適応 | 同行回数、新人の独り立ち期間 |
| 記録・計画書のレビュー | ①理念の行動化 ⑤約束履行 | レビュー件数、記録期限遵守率 |
| 連携先訪問（ケアマネ・病院） | ⑧信頼と求心力 | 訪問件数、指名紹介数 |
| 困難事例の相談役・同席 | ②察知と発信 ③当事者責任 | 相談対応件数、事故の未然防止 |
| 勉強会の企画・実施 | ⑦学習と適応 | 実施回数、参加者の行動変化 |
| 業務改善・仕組み化 | ③当事者責任 | 改善提案と実装件数 |

> **これが本制度の心臓部です。**
> 「75件に下げます」だけを通達すると収益が落ちます。
> 「75件に下げます。**空いた17時間で何を返すかを一緒に決めます**」まで言い切ってはじめて成立します。

## 4. ボーダーの運用ルール（超過・未達の扱い）

| 状態 | 扱い |
|---|---|
| ボーダーを**超えた** | **本人の責任にしない。** 管理者の配置設計の問題として扱う。2ヶ月連続超過は管理者評価の②察知と発信でマイナス |
| ボーダーの **90〜100%** | 正常。標準 |
| ボーダーの **90%未満** かつ NVA枠の成果がある | 正常。NVA枠で評価 |
| ボーダーの **90%未満** かつ NVA枠の成果がない | 面談対象。件数を戻すか、NVA枠の使途を組み直す |

**「ボーダー超過は本人の頑張り」として賞賛しない**ことを徹底してください。
超過を賞賛した瞬間、この制度は死にます。超過は**管理者の設計ミス**として扱います。

## 5. 収支を落とさない条件（ここを外すと制度ごと潰れます）

拠点の粗利はおおまかに次の式です。

```
拠点粗利 ＝ （訪問件数 × 1件あたり単価 × 稼働率） − 人件費 − 固定費
```

件数を下げるなら、**残り3つのどれかで取り返す**必要があります。取り返し方は3つだけです。

### (A) 1件あたり単価を上げる

| KPI | 見るもの | 目安の動かし方 |
|---|---|---|
| 加算取得率 | 緊急時訪問看護加算、特別管理加算、看護体制強化加算 等 | 算定要件を満たす利用者で取り漏れていないか、月次で全件チェック |
| 医療保険比率 | 医療／介護の構成 | 重症度の高い依頼を受けられる体制か |
| 長時間・複数名訪問 | 該当ケースの算定 | 要件と実態が一致しているか |

> **必ず「適正算定」とセットで運用してください。** 単価向上を評価に入れると、
> グレーな算定への圧力が必ず生まれます。⑥誠実さ（M6-2）で歯止めをかけています。

### (B) 稼働率を上げる（＝件数を増やさずに空白を減らす）

| KPI | 見るもの |
|---|---|
| キャンセル率・空き枠率 | 直前キャンセルの再配分ができているか |
| 初回訪問までのリードタイム | 依頼から初回訪問まで何日か（長いと他社に流れる） |
| 移動時間比率 | エリア割り・ルート設計の最適化余地 |

### (C) 離職を減らす（実はここが一番効く）

看護師1名の離職コストは、採用費＋立ち上がり3ヶ月の生産性低下＋既存スタッフの負荷増を合わせると、
**おおむね100〜200万円規模**になります（自社の実数で置き換えてください）。

```
件数を10件下げるコスト（1人あたり）
  ≒ 10件 × 単価 × 12ヶ月 ＝ 年間の売上減

離職1名を防ぐ効果
  ≒ 採用費 + 教育コスト + 3ヶ月分の生産性ロス + 残った人の超過負荷
```

**30名超の組織なら、年間の離職を2〜3名減らせれば、
全中堅職員の件数を10件下げた分はほぼ回収できます。**
この試算を自社の実数で作ることが、経営として75件を決断する根拠になります。

### 移行時のモニタ指標（月次で必ず並べて見る）

| 指標 | 悪化したら疑うこと |
|---|---|
| 1人あたり件数の**分布**（平均ではなく） | 平均が75でも、95と55が混在していれば設計は失敗 |
| 加算取得率 | 単価での取り返しが効いていない |
| キャンセル率／空き枠率 | 件数減が稼働の緩みに変わっている |
| 記録の期限遵守率 | NVA枠が「休憩」に化けている可能性 |
| 新規紹介件数 | 連携先訪問というNVA枠の使途が機能していない |
| パルスサーベイ（晴れ／曇り／雨） | 件数を下げても負荷が下がっていない＝重症度かオンコール側の問題 |
| 離職率・在籍月数 | 制度全体の最終KPI |

## 6. 「仕組み化」の射程を間違えない

仕組み化できるものと、できないものがあります。ここを混ぜると制度が現場に嫌われます。

| 仕組み化**できる**（＝本パッケージが担う） | 仕組み化**できない**（＝人に依存する） |
|---|---|
| 情報共有・記録精度 | 空気の察知 |
| 教育導線・同行計画 | 板挟みの調整 |
| 緊急連絡・オンコール体制 | 信頼形成 |
| 法令遵守・期限管理 | 危機予測 |
| 業務漏れ防止 | 感情制御 |
| 評価・処遇の手続き | 倫理判断 |

**仕組みは土台、最後は人です。**
本パッケージの評価項目が「行動」ではなく「行動＋その根拠となる事実」を求めているのは、
右列を数値化するのではなく、**右列が発揮された事実を拾い上げる**ためです。

管理者を仕組みだけで量産しようとすると、次が起きます（詳細は [09](09_制度が壊れる兆候.md)）。

- 「マニュアルにないので分かりません」で止まる管理者が増える
- 「ルール通りやりました」という他責が増える
- 数字は正常なのに現場は崩壊寸前、という状態を見逃す
