# 連載「人事の失敗図鑑」設計書

会社の発信として、代表と人事副社長（三井斗真）で運用する note 連載の設計。
このディレクトリのファイルは、記事を書く前に毎回開くもの。

**連載名：人事の失敗図鑑**／著者名義：**元管理者Ns**（三井斗真）
「Ns」は看護師（Nurse）の意。「元管理者」の肩書きが、この連載の説得力の土台になっている
（管理者を経験した人間が、人事として管理者の失敗を語る）ので、名義には必ず入れる。
マガジンのロゴは `assets/logo.jpg`。

## 1. この連載が何のためにあるのか

**目的は採用。** それも「応募数」より先に「入ってから辞めない人が応募してくる」状態をつくる。

訪問看護の求職者がいちばん恐れているのは、待遇の低さではなく **「面接で聞いた話と、入ってからの現実が違うこと」** です。
一人で家に上がる仕事で、判断も責任も自分に返ってくる。だから求職者は「この会社は都合の悪いことを言うか」を見ている。

求人票やコーポレートサイトで「アットホームな職場です」と書いても、この不安は1ミリも減りません。減らせるのはひとつだけ、
**人事の責任者が、自分がやった人事の失敗を、実名で、具体的に、公開の場で書くこと** です。
これは競合が真似できません。真似するには、同じだけの失敗を認める覚悟が要るからです。

だからこの連載の裏テーマは「失敗の告白」ではなく、**「うちは選考で嘘をつかない」ことの証明** です。

参考にいただいた記事のなかに、この連載の大義名分になる一行がありました。

> 失敗という財産をどれだけ後輩に残してやれるか、それこそが幹部の仕事ではないでしょうか。

連載紹介文や第1回の冒頭に置くと、なぜ人事の責任者が失敗を書くのかを1行で説明できます。
**ただし引用の前に一次ソースを必ず確認してください**（`swipe-file.md` 参照）。出典が X のスクレイプのままでは会社名義で載せられません。
自罰的な反省文で終わる記事は目的を達成しません。毎回、**「だから今、うちの選考と入社後はこうなっている」** まで書き切ってはじめて採用に効きます。

## 2. 主役と役割分担

- **語り手：元管理者Ns（三井斗真・人事副社長）** — 一人称で、自分が下した判断とその誤りを書く。「元管理者」を名乗るのは、管理者だった人間が管理者の失敗を語ることが、この連載の説得力の土台だから。
- **代表** — 各記事の末尾に「代表コメント」3〜5行。経営としてその失敗をどう見ているか、何を許容し何を許容しなかったか。
  - これがあることで、個人の反省文ではなく **会社としての発信** になる。
  - 代表の稼働は「読んで3行書く」だけに固定する。ここを重くすると連載は必ず止まる。
- **公開前チェック** — 代表＋もう1名（当事者に近くない人）。詳細は `guardrails.md`。

## 3. 記事の型（短編コラム）

**1本＝1,000〜1,500字。ひとつの場面、ひとつの turn。**

当初はケーススタディ形式（5ブロック・2,500〜4,000字）で設計していましたが、読み手の負担が大きすぎたので短編コラムに変えました。
実際、第1回は4,000字近くありました。4本に割ったら、全部が読みやすくなりました。

1. **場面** — いきなり場面から始める。セリフがあれば1行目に
2. **状況** — 何が起きていたか。数字を1つ。評価と反省は混ぜない
3. **問い、または誤った答え** — 短いコラムでも、謎はいる
4. **turn** — 気づいたこと。**1本に1つだけ**
5. **着地** — 今の自分に引きつけて。きれいにまとめず、解けていない一行を残す

自己紹介は**末尾の署名だけ**。毎回冒頭で名乗ると、それだけで読者が離れます。

詳細と文例は `article-template.md`。

### 「何を変えたか」は、別の回に分ける

以前の型では毎回「何を変えたか」に実在する具体物を書く決まりでしたが、短編コラムでそれをやると長くなります。
**3本に1本、仕組みだけを短く出す回を挟んでください。**「うちの面接で必ず聞く3つの質問」のような回です。

これでコラムは読みやすいまま、連載としては「ちゃんと変えている会社」だと伝わります。

## 4. 運用

| 項目 | 決め |
| --- | --- |
| ペース | 週1本・火曜 7:00 公開。短いので週2本も可能 |
| 文量 | **1,000〜1,500字。** 1,800字を超えたら2本に割る |
| タイトル | 因果か問いを一行で（連番は付けず、マガジンの並びで管理）。人事用語を主語にしない。詳細は `article-template.md` |
| 執筆 | 前週の金曜までに下書き → 月曜に代表チェック → 火曜公開 |
| ストック | 常に2本先まで書き溜める。1本でも切らすと連載は止まる |
| X 導線 | 公開当日に2投稿へ分解（①場面 ②turn＋リンク）。リンクは1投稿目に置かない |
| 配信先 | 9月は note ＋ X ＋ Threads。**Instagram は10月から。** 詳細は `distribution.md` |
| X の純度 | 人事副社長のアカウントに日常投稿を混ぜない。フォロワーが求めていない投稿はアカウントの定義をぼかす |
| プロフィール | **第1回の公開前に整える。** 投稿を読んだ人が「この人は何者か」を見に来る。採用リンクと連載マガジンを置いておく |

**書き溜めルールが最重要です。** 発信が続かない理由の9割は「ネタ切れ」ではなく「その週に書く時間がなかった」です。
ネタが尽きたと感じたら `failure-inventory.md` を開く。

## 5. 何を見て成否を判断するか

note の PV とフォロワーは先行指標にすぎません。目的は採用なので、下の3層で見ます。

- **先行**：読了率、スキ、X の保存数 → 記事の質のフィードバック
- **中間**：記事から採用ページ・カジュアル面談への遷移数
- **本命**：①応募のうち note 経由の比率 ②**初回面談で連載に言及した応募者の割合** ③内定承諾率 ④入社6ヶ月定着率

**②を取るための仕込みを、第1回公開前に必ず入れてください。**

- 応募フォームに「当社を知ったきっかけ」の自由記述欄を追加する
- 初回面談の冒頭質問に「note は読みましたか。どの回ですか」を定型で入れる

この2つがないと、連載が効いているのかどうか永久に分かりません。ダッシュボードより先にこれです。

## 6. 参考にする発信について

共有いただいた X の長文記事14本を分析し、輸入する型（数字を冒頭に置く／「×〇」の対比／保存用チェックリスト／STEP形式／番号付きの実践方法）と、
**輸入しないもの**（煽り型のタイトル術／副業・情報商材の構成／属人性を賛美するマネジメント論）を `swipe-file.md` にまとめました。

うまくいっている発信の型でも、読者が違えば逆に働きます。
**この連載の読者は求職者と、地域のケアマネ・医療機関です。** 素材を追加するときは、必ず「どの回に効くか」と「輸入しないもの」の両方を書いてください。

なお、最初に共有いただいた X の URL リストは、この作業環境から本文を取得できませんでした。
本文をテキストで貼っていただければ、同じように分析して `swipe-file.md` に追記します。
