# 記事テンプレート（ケーススタディ形式）

このファイルをコピーして下書きを作る。**ブロックの順番は変えない。**
順番を固定するのは、書く時間を短くするためと、読者に「この連載は毎回ちゃんと仕組みまで書く」と学習させるため。

---

```markdown
# 【失敗人事 #0N】〜したら、〜だった

（リード：3〜5行。結論＝自分がやった失敗を、最初の3行で言い切る。
　前置き・自己紹介・業界の一般論はここに書かない。読者は1行目で離脱する。）

例：
> 3年前、私は求人票に「未経験歓迎」と書いた。
> 応募は増えた。面接も埋まった。そして、いちばん来てほしくない人が集まった。
> 悪いのは応募してくれた人ではない。求人票を書いた私だ。

---

## 何が起きたか

（事実と時系列だけ。評価と反省をここに混ぜない。**数字を最低1つ入れる。**
　「応募が◯件」「◯人採用して◯人が半年以内に辞めた」「◯ヶ月放置した」）

## 私は、何をどう判断したか

（当時の自分の意思決定と、その時点での根拠。ここが記事の心臓部。
　**弁解も後知恵も入れない。**「今思えば」は次のブロックで使う言葉。
　当時の自分がどれだけ真剣に、それでも間違えたかを書けるほど記事は強くなる。）

## どこが間違っていたか

（原因を3つに分けて書く。この分解が読者の持ち帰りになる。）

1. **判断の誤り** — 私が何を取り違えていたか
2. **情報の欠落** — 判断する前に、本来知っておくべきだったこと
3. **仕組みの不在** — そもそも個人の判断に委ねてはいけなかったこと

（人事の失敗のほとんどは3。「自分の未熟さ」で終わらせると、次も同じことが起きる。）

## 何を変えたか

（**この記事でいちばん重要なブロック。ここが薄いと、ただの反省文になり採用に効かない。**
　今実際に動いている具体物を書く。抽象論は禁止。
　- 面接の質問文なら、質問文そのものを引用する
　- チェックリストなら、項目を出す
　- 面談のタイミングを変えたなら、何日目に何を聞くか書く
　求職者はここを読んで「この会社は選考で嘘をつかないな」と判断する。）

## まだ解けていない宿題

（正直さの担保。今も困っていることを1つ書く。
　ここがない記事は、失敗を語る体裁をとった自慢に見える。）

---

### 代表コメント

（3〜5行。経営としてこの失敗をどう見ていたか、何を許容し、何を許容しなかったか。
　人事副社長の反省を追認するだけの文にしない。**視点がずれているほど良い。**）

---

※ 本稿の事例は、個人が特定されないよう複数の出来事を再構成しています。

（採用導線：抑制的に1〜2行。煽らない。）
> うちの訪問看護ステーションでは、一緒に働く仲間を探しています。
> こういう失敗をしてきた組織でよければ、一度話を聞きに来てください。→ ◯◯
```

---

## 書くときのルール

| ルール | 理由 |
| --- | --- |
| リードで結論（自分の失敗）を言い切る | 前置きを読む人はいない |
| 主語は常に「私」 | `guardrails.md` 3。他人の人格評価は連載を殺す |
| 数字を最低1つ | 具体性が誠実さの証拠になる |
| 「何を変えたか」に実在する具体物を書く | ここが記事の商品価値。抽象論なら書かないほうがまし |
| 人事用語を減らす | 「タレントマネジメント」「エンゲージメント」は読者の現場語ではない |
| 「宿題」を必ず書く | 完結した成功譚は疑われる |
| 業界の一般論を書かない | 読者が読みたいのは、あなたが実際にやった判断だけ |

## タイトルの型

`【失敗人事 #0N】` ＋ **因果を一行にした事実**。

- ○ 「いちばん優秀な看護師を管理者にして、二人まとめて失った」
- ○ 「合わないと分かっていて、半年放置した」
- ✕ 「人事における登用の難しさについて」（人事用語が主語／因果がない）
- ✕ 「managerの選び方、3つのポイント」（ノウハウ記事に見えて、この連載の価値が消える）

## X への分解（公開当日）

1. **失敗の一行** — リードの1〜2行をそのまま。リンクは貼らない
2. **当時の判断** — なぜそう決めたか。ここで共感が取れる
3. **今の仕組み ＋ リンク** — 「④何を変えたか」の要点と note のリンク

リンクを1投稿目に置かない。1投稿目はリンクなしで伸ばして、3投稿目で回収する。
